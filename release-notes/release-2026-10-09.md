## Highlights

The SCM family ships: `scm-connection`, `scm-repository` and `scm-oauth-app` replace Core's
Gitea-only coverage with one API that works against Gitea and GitHub, built entirely on OpenTofu.
`gitea-user`/`-org`/`-team`/`-repository` and the `random-password` utility are retired in the same
release — archived, not deleted, since no cluster ever ran them. Packages are now grouped by API
group (`package/<group>/<name>/`), the OCI registry moved to `ghcr.io/wxops-idp`, and
`development-docs/` now holds everything about building and deciding Core, separate from the
user-facing docs in `docs/`.

**The four `gitea-*` removals are the one breaking change in this release**, allowlisted in
[`tests/api-compat-allow.yaml`](../tests/api-compat-allow.yaml). An operator with an existing
`XGiteaUser`/`XGiteaOrg`/`XGiteaTeam`/`XGiteaRepository` XR will see it fail validation once this
release's XRDs install — there is no `gitea-*` XRD in this release to validate against, and no
migration path, because retiring these packages was a direct decision, not a phased deprecation:
real testing found no cluster had ever run them. If one somehow exists, read it off before
upgrading; its Terraform state and the Gitea objects it manages are untouched by the removal
itself, but Core stops being able to reconcile or delete them. Source, tests, examples and docs for
all four packages are kept, not deleted — `package/platform/archives/<name>/` and the sibling
`_archives/` folders — see [RFC-003 §Removing the old kinds](../development-docs/rfc/003-scm-connections-and-resources.md).

The `random-password` utility composition is retired the same way (`package/platform/archives/random-password/`).
It was never published as its own OCI package, so it carries no formal compatibility tier, but any
cluster with a live `XRandomPassword` XR loses the ability to reconcile it the same way.

Every other change in this release is additive: `scm-connection`, `scm-repository` and
`scm-oauth-app` are new packages (`safe` by definition — nothing existing depends on them yet), and
`platform-database-clusters`/`tenant-database`/`tenant-app` carry no schema change, only a rebuild
under the new package layout and registry.

## Upgrade notes

- **OCI registry moved.** Package images are now `ghcr.io/wxops-idp/wxops-core/<package>`, not
  `ghcr.io/wxops/wxops-core/<package>`. Update any pinned `spec.package` reference and re-run
  `make install` (or your GitOps equivalent) — `package/install/` in this release already points at
  the new org.
- **`make providers` no longer installs `provider-terraform`.** It's archived in
  `providers/archive/`, not auto-applied. If a cluster still runs a `gitea-*` XR on it (see
  Compatibility above), apply `providers/archive/provider-terraform.yaml` and its `ProviderConfig`
  by hand before upgrading — don't let the retired provider disappear out from under a resource
  Core can no longer manage.
- **Package layout changed on disk.** `package/<name>/` is now `package/<group>/<name>/`
  (`platform`, `scm`). This only matters if something outside this repo reads source paths
  directly (e.g. a fork, a vendored copy) — the served API and OCI image names are unaffected.
