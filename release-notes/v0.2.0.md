# Release Notes

## Highlights

This release adds the **database and application layers** of W'xOps Core on
top of the existing Gitea management packages: a platform team provisions
shared PostgreSQL clusters (`XPlatformDatabaseCluster`), tenants get
self-service databases on those clusters with Vault-backed credentials
(`XTenantDatabase`), and tenants get a full application scaffold
(`XTenantApp`) — `Deployment` + `Service` + `Ingress`, golden-path health
checks, an optional local-debugging twin, cert-manager-issued TLS, and SSO
via Traefik/oauth2-proxy — that wires Vault/database secrets produced by the
platform via simple `secretsFrom` toggles. All three new packages use
[`function-kcl`](https://github.com/crossplane-contrib/function-kcl) for
their composition logic, with `kcl/` as the source of truth synced into each
`composition.yaml` via `make kcl-sync`/`make kcl-check`.

### Added — `XPlatformDatabaseCluster` (`package/platform-database-clusters/`)

Platform-managed [CloudNativePG](https://cloudnative-pg.io/) cluster with
pooler and Vault credential seeding — the foundation `tenant-database`
provisions tenant databases on top of.

- `clusterName` / `namespace` / `instances` (1–9, default `1`) /
  `postgresVersion` (default `16`) / `storageSize` (default `8Gi`).
- `enablePooler` (default `true`) — PgBouncer `Pooler` (RW), with
  `poolMode` (`transaction`/`session`).
- `readReplica.enablePooler` — second, read-only PgBouncer `Pooler`
  (`{clusterName}-ro-pooler`).
- `postgresConfig.tuning.*` — common `postgresql.conf` tuning knobs
  (`maxConnections`, `sharedBuffers`, `workMem`, `effectiveCacheSize`,
  `randomPageCost`, `statementTimeout`, etc.) plus
  `postgresConfig.extraParameters` (free-form) and `postgresConfig.pgHba`
  (additional `pg_hba.conf` rules).
- `monitoring.enablePodMonitor` — Prometheus Operator `PodMonitor`.
- `backup.*` — Barman object-store backup (S3/GCS/Azure-compatible),
  `ScheduledBackup` with configurable `schedule`/`retentionPolicy`.
- `managedRoles[]` — additional cluster-wide PostgreSQL roles, each fanning
  out to a Password generator + `ExternalSecret`/`PushSecret` bundle and an
  entry in `spec.managed.roles[]` on the CNPG `Cluster`.
- Superuser credentials are seeded to Vault at
  `platform/database-clusters/{clusterName}/root-creds` via `PushSecret`.

### Added — `XTenantDatabase` (`package/tenant-database/`)

Tenant-facing PostgreSQL database on a platform cluster, with continuously
reconciled per-tenant role and Vault-backed credential sync.

- `tier` (default `"shared"`) — platform-defined cluster pool selector.
  `clusterRef`/`clusterNamespace` are **optional**, defaulted from `tier`
  via a platform-managed map (`shared` → `cluster-a` / `cnpg-system`).
  Explicit `clusterRef`/`clusterNamespace` always win.
- `dbName`, `owner`, `tenantNamespace` (required), `extensions[]`
  (e.g. `uuid-ossp`, `pgcrypto`, `postgis`, `vector`), `vaultSecretStoreName`.
- Per-tenant `provider-sql` `Role` continuously reconciled (creates the role
  if missing, runs `ALTER ROLE` on password change) — independent of the
  shared CNPG `Cluster` spec.
- Connection bundle pushed to Vault at
  `tenant/{owner}/{dbName}/connection-creds` and synced back into
  `tenantNamespace` as a Secret for app pods.

### Added — `XTenantApp` (`package/tenant-app/`)

Tenant application scaffold: `Deployment` + `Service` + optional `Ingress`
(+ optional debug `devSpace` twin), following `app.kubernetes.io/*` label
conventions (`name`, `instance`, `managed-by: crossplane`). Deliberately
stops at the application workload — Vault-backed secrets and databases are
platform-level concerns, wired in via `secretsFrom` (see below).

- `ingress.className` defaults to `"traefik"` (W'xOps' standard ingress
  controller).
- `templateId` / `repository.url` — optional catalog-linking metadata.
  Applied as `wxops.cloud/template-id` / `wxops.cloud/repo-url` annotations
  on every composed resource, for portal/Backstage catalog wiring. See the
  new [app-onboarding guide](https://github.com/wxops/wxops-core/tree/main/docs/user-guide/app-onboarding.md) for the end-to-end
  flow (pick `appFlavor` → pick `templateId` → create/import a
  [`gitea-repository`](https://github.com/wxops/wxops-core/tree/main/docs/api-reference/gitea-repository.md) → scaffold → `tenant-app`).
- `labels` / `deploymentAnnotations` / `podAnnotations` — free-form
  extras merged onto composed resources. The standard
  `app.kubernetes.io/*`/`wxops.cloud/*` labels always win (selectors depend
  on them).
- `rolloutStrategy` — `Deployment.spec.strategy`
  (`RollingUpdate`/`Recreate`, with `maxSurge`/`maxUnavailable`), relevant
  once `replicas > 1`.
- `secretsFrom.{app,database}` — simple enable + default-naming toggles that
  add `envFrom.secretRef` entries for Secrets provisioned out-of-band by the
  platform/GitOps (an `ExternalSecret`/`PushSecret` for Vault app secrets, an
  [`XTenantDatabase`](https://github.com/wxops/wxops-core/tree/main/docs/api-reference/platform/tenant-database.md)'s connection-creds for the
  database). `tenant-app` only wires the reference by name — it does not
  provision or wait for the Secret, so the referenced Secret(s) **must exist
  before (or alongside) this XR** or the Pods fail with
  `CreateContainerConfigError`. See the
  [go-live ordering contract](https://github.com/wxops/wxops-core/tree/main/docs/api-reference/platform/tenant-app.md#vault-secrets--databases).
- `envFrom[]` — additional `secretRef`/`configMapRef` sources, appended
  after `secretsFrom`.
- `reloader.enabled` — adds `reloader.stakater.com/auto: "true"` for
  [Stakater Reloader](https://github.com/stakater/Reloader) rolling
  restarts on ConfigMap/Secret changes.
- `ingress.tls.clusterIssuer` — if set (and `tls.enabled`), adds the
  `cert-manager.io/cluster-issuer` annotation so
  [cert-manager](https://cert-manager.io/) automatically issues a
  certificate into `tls.secretName`. Requires cert-manager and the named
  `ClusterIssuer` to exist in-cluster.
- `ingress.auth.enabled` — SSO via oauth2-proxy: adds the
  `traefik.ingress.kubernetes.io/router.middlewares` annotation referencing
  the `auth-errors`/`forward-auth-redirect` Traefik `Middleware` CRDs
  (ForwardAuth + redirect-to-login on `401`). Both `Middleware`s are mirrored
  into every tenant namespace by the platform — `tenant-app` only
  references them.
- `environment` (`dev` | `staging` | `prod`, default `dev`) — applied as the
  `wxops.cloud/environment` label. Pure metadata, intended to pair with an
  ArgoCD ApplicationSet matrix generator (apps × environments).
- `appFlavor` (`webapp` | `ai` | `ai-webapp` | `geo-webapp` | `search-webapp`,
  default `webapp`) — applied as the `wxops.cloud/app-flavor` label, purely
  metadata for platform-level automation (e.g. the portal choosing
  `pgvector`/`postgis`/etc. extensions when provisioning a database for this
  app via `secretsFrom.database`). Does not affect any resource composed by
  this XR.
- `probes` — golden-path health checks. `liveness`/`readiness` default to
  **enabled** whenever `service.enabled` is true (the default), as
  `GET /healthz` and `GET /readyz` against `containerPort`. `startup` is
  opt-in (disabled by default) for slow-starting apps. All paths/timings are
  overridable; see [Golden Path Contract](https://github.com/wxops/wxops-core/tree/main/docs/api-reference/platform/tenant-app.md#golden-path-contract).
- `devSpace` — optional debug "twin" `<appName>-dev` Deployment, scaled to
  `0` by default, sharing the main Deployment's image/env/`envFrom`
  (including any `secretsFrom`-managed secrets) but with **no
  `Service`/`Ingress`** of its own. Intended as a target for
  Telepresence/Mirrord/`kubectl exec` so local development gets the same
  environment as production without exposing anything externally — see
  [local-dev-tunneling.md](https://github.com/wxops/wxops-core/tree/main/docs/local-dev-tunneling.md).

### Platform/tooling additions

- **New shared providers** (`providers/`): `provider-kubernetes` (plain K8s
  manifests via `kubernetes.crossplane.io/v1alpha2 Object`), `provider-sql`
  (per-tenant PostgreSQL role reconciliation), `function-kcl`,
  `function-go-templating`, plus a `ProviderConfig` for
  `provider-kubernetes`. Apply once per cluster via `make providers` before
  installing the new packages.
- **KCL composition tooling** — `kcl/{platform-database-clusters,
  tenant-database, tenant-app}/main.k` are the source of truth for these
  Compositions, embedded into `package/{pkg}/composition.yaml` via the new
  `.gitea/scripts/kcl-sync.py` (`make kcl-sync` / `make kcl-check`). See
  [`kcl/README.md`](https://github.com/wxops/wxops-core/tree/main/kcl/README.md) for the rationale (KCL vs Go
  templating) and sync workflow.
- **New `docs/` directory** — full `spec.parameters` API reference for every
  XRD, including the new packages' Golden Path Contract, `devSpace`
  guidance, the SSO/cert-manager ingress sections, and a new
  [app-onboarding guide](https://github.com/wxops/wxops-core/tree/main/docs/user-guide/app-onboarding.md) tying together the
  templates catalog, `gitea-repository`, and `tenant-app`.
- **New `examples/`** — minimal claim YAML for
  `platform-database-clusters`, `tenant-database`, and `tenant-app`.
- `package/install/` and `package/dev/` kustomizations updated to include
  all three new packages; `Makefile`'s `PACKAGES` list extended accordingly.

## Upgrade notes

- Run `make providers` to install the new shared providers/functions
  (`provider-kubernetes`, `provider-sql`, `function-kcl`,
  `function-go-templating`) before installing
  `platform-database-clusters`/`tenant-database`/`tenant-app`.
- All three new packages are additive — no changes to existing
  `gitea-*`/`random-password` packages or their XRDs.
- `devSpace` on `XTenantApp` is opt-in (`enabled: false` by default) — no
  impact unless explicitly enabled.
- `ingress.tls.clusterIssuer` and `ingress.auth.enabled` are both opt-in
  annotations only — `tenant-app` does not install cert-manager, oauth2-proxy,
  or the `auth-errors`/`forward-auth-redirect` `Middleware` CRDs. These must
  already exist in-cluster (and, for SSO, be mirrored into each tenant
  namespace, e.g. via Kyverno `generate`) before enabling either field.
- `secretsFrom.{app,database}` only add `envFrom.secretRef` entries by name —
  the referenced Secrets must be created before (or alongside) the XR, or
  Pods fail with `CreateContainerConfigError`. See the
  [go-live ordering contract](https://github.com/wxops/wxops-core/tree/main/docs/api-reference/platform/tenant-app.md#vault-secrets--databases).
