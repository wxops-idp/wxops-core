## Highlights

Core now carries identity as well as source control. A new **`auth.wxops.cloud`** group — `oidc-connection`, `oidc-connector`, `oidc-client` and `oidc-static-password` —
writes the records the W'xOps `dexidp` chart turns into a Dex configuration, with the per-org team allow-list *generated* from labelled `XScmTeam`s, and `scm-team` joins the
`scm` family to feed it. Every package now also reports **`synced` and `syncMessage`**, and `ready` is false while a composed resource's last apply failed — a failed
update used to hide behind a `Ready=True` left over from the last success. `scm-connection` summarises the org it points at in its status, and `scm-oauth-app` gains a
required `vendor` so a GitHub connection no longer fails on the Gitea provider.

**`scm-oauth-app` now requires `spec.parameters.vendor` (`gitea` or `github`).** The module is chosen by it, as on `scm-repository` and `scm-team`: the Gitea provider
calls its base URL the moment it is configured, so one module that declared it failed on a GitHub connection. An existing `XScmOAuthApp` that does not set `vendor` fails
validation once this release's XRD installs, and its Workspace keeps running whatever module it last rendered until the field is added. A first version defaulted `vendor`
to `gitea`; on a real cluster Crossplane rendered an existing XR without the defaulted value and left the Workspace on a placeholder module, so it is required instead.

Rolling back is **lossy** for any `XScmOAuthApp` that already sets `vendor`: reinstalling the previous XRD prunes the field, and a GitHub application goes back to the
single Gitea module that cannot serve it. A Gitea application is unaffected either way.

Everything else is `safe` and additive: `synced` and `syncMessage` on every kind, and for `scm-connection` the `org`, `repositories` and `teams` status plus one extra
read-only Workspace per connection that has an `org`.

## Upgrade notes

- **Add `vendor` to every existing `XScmOAuthApp`** (`gitea` or `github`, matching its `scmRef` connection), then re-apply. For the one Gitea application most clusters
  have, that is `vendor: gitea`. Do it before upgrading the XRD, or immediately after.
- **`ready` can now go false on a resource that used to read true.** A kind whose last apply failed reports `ready: false`, `synced: false` and the provider's message in
  `syncMessage`; that is the intended change, not a regression. The native XR `Ready` condition follows. A failing credential push, a scheduled backup, or the connection's
  org inspection is shown in `syncMessage` but does not flip `ready`.
- **`scm-connection` adds a read-only `inspect` Workspace** when `org` is set. It needs a token that can read the org; on Gitea, listing teams also needs the token's user to be
  a member of the org. If it cannot run, `status.org` stays absent and the reason is in `syncMessage` — the connection itself is unaffected.
- **New in `scm-team`:** on GitHub, `members[]` must already belong to the org or the apply is refused naming them; on Gitea, adding a member is how they join. On Gitea,
  `permission` is `read` or `write` (`admin` is rejected) and `unitPermissions` lays per-unit overrides over `units`.
- **The `auth` group needs the `dexidp` chart** (or another consumer of the OpenBao records). Core writes records only: it renders no config and restarts nothing.
  Clients are platform-defined; tenants are not meant to create them. Rotation is by `rotation.generation` only — there is no scheduled rotation.
- Release tooling: `make release` clears the `scm-oauth-app` allowance in `tests/api-compat-allow.yaml` for this release.

## Known issues

- High availability and scale are untested: how a bad config behaves across Dex replicas under the chart's `maxUnavailable`, what happens with a non-valid `bcrypt` hash in a
  static-password record, and the `scm.wxops.cloud/oidc-login` selector at a large team count. Tracked as RFC-004 open question 8.
- A GitHub connection's org inspection lists members as a side effect of listing repositories, which costs extra API calls for a large org.
- `XOIDCConnector` does not de-duplicate a team that is both hand-listed and generated; the entry appears twice.
