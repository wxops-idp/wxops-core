## Highlights

An SCM login now decides what a person may do in a cluster. Three new kinds in **`auth.wxops.cloud`** take a team from the SCM to Kubernetes permissions:
**`XPersona`** collects who a title applies to (teams by label, groups, users, agents' ServiceAccounts), **`XPersonaBinding`** binds it to aggregated roles —
`RoleBinding`s per owned namespace, or a `ClusterRoleBinding` to the Platform API roles — and **`XPlatformPolicy`** narrows what RBAC allowed with one of eight
reviewed Kyverno CEL templates: write only what your team owns, no Secrets by hand, exec only for a persona in its own namespaces, protected objects, bindings
only through `XPersonaBinding`, workloads only as their own team's ServiceAccount, and Namespaces and their owner labels for the platform team. Proven on a
cluster before release: 50/50 acceptance rows, and the same rows through real Dex and Pinniped logins ([RFC-009 results](../development-docs/rfc/009-scm-personas.md#spike-and-acceptance-results-2026-11-04)).

Every change is additive: three new packages, no existing package touched. Rolling back is removing the three packages; their XRs go with them, and the
`RoleBinding`s and Kyverno policies they composed are deleted. Nothing else depends on them.

**One deliberate exception to "compositions never emit RBAC".** `persona-binding`, and only it, emits `RoleBinding` and `ClusterRoleBinding` — never a `Role` or
`ClusterRole`, never `cluster-admin` — to the roles `provider-kubernetes` holds `bind` on by name. `tests/invariants.py` enforces it; an ADR records it once
RFC-009 is accepted.

## Upgrade notes

- **Prerequisites at bootstrap** (not installed by W'xOps): Kyverno **v1.19 or later** — the policies are `policies.kyverno.io/v1` — and Pinniped. People reach
  every cluster through the Concierge's **impersonation proxy**, never the API server directly. **Kubernetes v1.36 is recommended**: Pinniped v0.46.0 is built on
  the 1.36 libraries, and on older clusters its proxy runs with failing watches. Restart the Concierge after a cluster upgrade.
- **Re-apply the providers** — `make providers`. `providers/` is now split into `functions/`, `packages/`, `rbac/` and `config/`, applied in that order with a
  target each (`make providers-functions`, …). New: the persona and Platform API aggregated roles (`rbac/aggregate-*.yaml`), `bind` for `provider-kubernetes` on
  exactly those roles plus write access to Kyverno policies, and `provider-vault` with its `vault-provider-config` ProviderConfig — its `vault-credentials`
  Secret is created out of band.
- **Personas bind the W'xOps roles, not `edit` or `admin`.** `wxops:persona-viewers`, `-developers` and `-owners` are `view` plus W'xOps write pieces — no
  impersonation of ServiceAccounts, no token requests, no Secret, ServiceAccount, Pod or RoleBinding writes. Only `wxops:persona-platform` keeps `admin`. The
  built-in `edit` and `admin` are not bindable through `XPersonaBinding`.
- **Label tenant namespaces** `auth.wxops.cloud/tenant-namespace: "true"` and `wxops.cloud/owner: <team>` — `scope: owned` and `owner-stamp` find them by those.
  Team names are matched exactly: use slug-form team names.
- **A persona holds SCM identities only:** a `system:` group or user is refused in `members`; a ServiceAccount joins by name through `members.serviceAccounts`.
- **`mode: Audit` only reports if Kyverno's reports controller runs.** Without it, an `Audit` policy neither blocks nor visibly records anything — use `Deny`
  (every template was proven in `Deny`). Put `rbac-guard` in `Deny` before the first persona binding exists.
- **Run Kyverno in high availability** — see Known issues.
- **Paths moved.** Examples are one `xr.yaml` per package at `examples/<group>/<name>/` (more variants are snippets on each API page), the API reference is at
  `docs/api-reference/<group>/`, and the RBAC-aggregation and OpenBao examples moved to `providers/rbac/examples/` and `providers/config/examples/openbao/`.
  `make render` is removed — the golden tests cover rendering.
- **Contributors:** the render engine is pinned in `tests/crossplane-version.txt` (v2.3.1). `WXOPS_RENDER=shared make test` renders the goldens in seconds on
  Linux; the default, and CI, stay isolated.

## Known issues

- **A graceful Kyverno shutdown opens a short unchecked window.** Scaling Kyverno to zero, an upgrade or a restart deletes its webhook configurations, so
  people's writes pass without policy checks until it serves again — about two minutes on the test cluster. Controllers, Crossplane and cluster-admin are never
  blocked by a Kyverno outage. Run Kyverno with several replicas; a guard that pauses people's writes while Kyverno's webhooks are gone is planned.
- **`Audit` mode and PolicyReports are undecided** (RFC-009 open question 9): Kyverno's reports controller writes back through the API server, so it is not
  relied on. The API server audit log is the record.
- **A second team cannot own another team's objects** — `payment-maintainers` does not own what `payment` owns. A team-to-owner mapping is planned.
- **Policies are cluster-wide:** a template cannot yet be limited to some namespaces (for example `Deny` in production, `Audit` elsewhere).
- **`environments` on `XPersona` is recorded, not enforced** — the gate waits for the multi-cluster cluster identity.
- **Kyverno skips `kube-system` and `kyverno`** for every policy. No team persona holds RBAC there; only `platform` does, and it is trusted.
- Argo CD and External Secrets Operator writes were not exercised in the acceptance run; neither is ever matched by a template, by design.
